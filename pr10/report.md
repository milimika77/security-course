# ПР №10. Обнаружение вторжений: fail2ban и Suricata

## 1. Настройка fail2ban

В ходе работы была выполнена настройка системы Fail2ban для защиты SSH-сервиса от атак перебора паролей. Для контроля неудачных попыток аутентификации использовался стандартный jail sshd.

Параметры jail до усиления защиты:

* maxretry = 3
* findtime = 600
* bantime = 600

Fail2ban анализирует системные журналы и отслеживает неудачные попытки входа по SSH. При превышении установленного порога IP-адрес нарушителя автоматически блокируется.

Для обнаружения атак использовался фильтр sshd, основанный на регулярных выражениях, которые распознают записи журналов об ошибках аутентификации и попытках подбора пароля.

## 2. Брутфорс через hydra

Для проверки работы механизма защиты была выполнена имитация атаки перебора паролей с использованием утилиты Hydra.

В ходе тестирования было установлено, что после нескольких неудачных попыток входа Fail2ban автоматически обнаруживает атаку и блокирует IP-адрес источника.

Результаты тестирования:

* Количество неудачных попыток до блокировки: 3
* Заблокированный IP-адрес: IP-адрес атакующей системы
* Время от начала атаки до блокировки: несколько секунд

После срабатывания защиты IP-адрес появился в списке заблокированных адресов Fail2ban.

## 3. Механизм блокировки

Fail2ban не фильтрует трафик самостоятельно. После обнаружения нарушения он создаёт правила межсетевого экрана.

Физическая блокировка IP-адреса осуществляется через iptables. При срабатывании создаётся цепочка вида f2b-sshd, в которую добавляется правило DROP или REJECT для атакующего адреса.

Таким образом, соединения с заблокированного IP перестают достигать SSH-сервиса до окончания времени бана.

## 4. Усиленная защита

Для повышения эффективности защиты были изменены параметры Fail2ban:

* maxretry = 2
* findtime = 300
* bantime = 1800
* bantime.increment = true
* bantime.factor = 2

После усиления политики система начала реагировать быстрее, поскольку для блокировки теперь требуется меньшее количество ошибочных попыток входа.

Использование параметра bantime.increment позволяет автоматически увеличивать продолжительность блокировки для повторных нарушителей. Каждая новая блокировка становится длиннее предыдущей.

Параметр factor определяет коэффициент увеличения времени бана.

Такая схема значительно осложняет проведение длительных атак перебора паролей.

## 5. Suricata

В рамках работы была настроена система обнаружения вторжений Suricata.

Для обнаружения подозрительной активности было создано собственное правило:

alert tcp any any -> any 22 (msg:"Custom SSH brute force detection"; threshold:type both, track by_src, count 5, seconds 60; sid:1000001; rev:1;)

Данное правило отслеживает обращения к SSH-сервису и генерирует предупреждение при превышении заданного количества подключений от одного источника за определённый промежуток времени.

После генерации сетевой активности правило успешно сработало и сформировало предупреждение в журналах Suricata.

Формат fast.log содержит краткую информацию о событии.

Формат eve.json предоставляет значительно больше данных:

* временную метку события;
* IP-адрес источника;
* IP-адрес назначения;
* используемый протокол;
* номер сигнатуры;
* категорию события;
* уровень критичности;
* дополнительную сетевую информацию.

Благодаря этому eve.json удобен для последующего анализа и интеграции с системами мониторинга.

## 6. Сравнение fail2ban и Suricata

| Характеристика            | Fail2ban          | Suricata                       |
| ------------------------- | ----------------- | ------------------------------ |
| Тип решения               | HIDS              | NIDS                           |
| Источник данных           | Системные журналы | Сетевой трафик                 |
| Обнаружение атак          | Да                | Да                             |
| Автоматическая блокировка | Да                | Нет (по умолчанию)             |
| Анализ сети               | Нет               | Да                             |
| Обнаружение брутфорса     | Да                | Да                             |
| Обнаружение сетевых атак  | Ограничено        | Да                             |
| Основное назначение       | Защита сервисов   | Мониторинг и обнаружение угроз |

Fail2ban ориентирован на защиту конкретных сервисов путём анализа журналов и автоматической блокировки нарушителей.

Suricata предназначена для анализа сетевого трафика и выявления различных типов атак на уровне сети.

## Контрольные вопросы

### 1. Чем IDS отличается от IPS? Можно ли считать fail2ban IPS?

IDS предназначена для обнаружения атак и формирования уведомлений о подозрительной активности. IPS не только обнаруживает атаку, но и автоматически принимает меры по её блокированию.

Fail2ban можно считать системой IPS, поскольку после обнаружения нарушения он автоматически блокирует источник атаки через межсетевой экран.

### 2. Почему атака на localhost обычно не приводит к блокировке?

По умолчанию адрес 127.0.0.1 находится в списке ignoreip и исключается из обработки Fail2ban. Для тестирования необходимо удалить localhost из списка исключений либо явно изменить параметр ignoreip.

### 3. Что произойдёт при maxretry=1000 и findtime=1?

Такая конфигурация будет практически бесполезной. Для блокировки потребуется слишком большое количество попыток за очень короткое время, поэтому большинство атак не будут обнаружены.

### 4. Разница между сигнатурным анализом и анализом аномалий

Сигнатурный анализ сравнивает события с заранее известными шаблонами атак.

Анализ аномалий выявляет отклонения от нормального поведения системы.

Созданное в работе правило Suricata использует сигнатурный подход.

### 5. Достаточно ли одной Suricata для защиты от брутфорса?

Нет. В стандартном режиме Suricata только обнаруживает атаку и формирует предупреждение. Блокировка источника автоматически не выполняется.

### 6. Что означает threshold:type both, track by_src, count 5, seconds 60?

Параметр означает, что Suricata отслеживает события по IP-адресу источника. Если от одного адреса будет зарегистрировано не менее пяти событий за 60 секунд, будет сформировано предупреждение.

### 7. Зачем использовать bantime.increment?

Постепенное увеличение времени блокировки позволяет эффективнее бороться с повторными атаками. Каждый новый бан становится длиннее предыдущего, что делает перебор паролей экономически и технически невыгодным для нарушителя.
