# ПР №4. Аудит событий: journalctl и auditd

## 1. journalctl — системный журнал

### Работа с журналами systemd

В ходе выполнения работы был изучен инструмент journalctl, предназначенный для просмотра и анализа системных журналов Linux.

Для просмотра последних записей использовалась команда:

```bash
journalctl -n 20
```

Каждая запись журнала содержит дату, время, имя узла, источник сообщения и само сообщение. Данные журналы позволяют отслеживать работу служб, ошибки системы и действия пользователей.

Для просмотра событий текущей загрузки системы использовалась команда:

```bash
journalctl -b
```

Также был изучен режим просмотра событий в реальном времени:

```bash
journalctl -f
```

Данный режим позволяет наблюдать появление новых записей журнала непосредственно во время работы системы.

### Что зафиксировал журнал о команде sudo cat /etc/shadow

После выполнения команды:

```bash
sudo cat /etc/shadow
```

в журнале были зафиксированы сведения о запуске команды через sudo, имени пользователя, времени выполнения и результате проверки полномочий.

Журнал позволяет определить:
- кто выполнил команду;
- когда была выполнена команда;
- какая команда была запущена;
- был ли доступ разрешён.

### Ошибки в системе с последней загрузки

Для поиска ошибок использовалась команда:

```bash
journalctl -p err -b
```

Были обнаружены системные ошибки и предупреждения, связанные с запуском отдельных служб и компонентов операционной системы. Подобные записи позволяют своевременно выявлять проблемы конфигурации и потенциальные угрозы безопасности.

### Статистика входов

Для анализа входов использовались журналы SSH и события аутентификации.

- Успешные входы фиксируются сообщениями типа Accepted.
- Неудачные попытки фиксируются сообщениями типа Failed.

Журналы аутентификации позволяют выявлять попытки подбора паролей и несанкционированного доступа.

## 2. auditd — настройка правил аудита

### Назначение auditd

Auditd является подсистемой аудита безопасности Linux, работающей на уровне ядра операционной системы.

В отличие от обычных журналов, auditd позволяет отслеживать:
- обращения к критическим файлам;
- изменение настроек безопасности;
- повышение привилегий;
- неудачные попытки доступа;
- удаление файлов;
- запуск процессов от имени root.

### Применённые правила аудита

В ходе работы были настроены правила мониторинга следующих объектов:

- /etc/passwd
- /etc/shadow
- /etc/group
- /etc/sudoers
- /etc/sudoers.d/
- /etc/ssh/sshd_config

Также были добавлены правила для:
- контроля отказов в доступе;
- контроля удаления файлов;
- контроля повышения привилегий.

### Разбор записи SYSCALL

Записи auditd содержат сведения о системных вызовах.

| Поле | Значение | Что означает |
|--------|--------|--------|
| auid | Audit User ID | Пользователь, выполнивший первоначальный вход |
| uid | User ID | Текущий пользователь процесса |
| euid | Effective UID | Эффективный пользователь, от имени которого выполняется действие |
| comm | Command | Имя выполняемой команды |
| exe | Executable | Полный путь к исполняемому файлу |

Особое значение имеет поле auid, поскольку оно позволяет установить настоящего инициатора действия даже после использования sudo.

### Что означает type=SYSCALL

Тип записи SYSCALL обозначает системный вызов ядра Linux.

Такие записи содержат наиболее полную информацию о действиях пользователя:
- открытии файлов;
- запуске процессов;
- изменении прав доступа;
- удалении объектов файловой системы.

## 3. Расследование инцидента

### Смоделированный инцидент

Для проверки возможностей системы аудита были выполнены действия от имени пользователя bob.

Были выполнены следующие операции:

1. Попытка чтения файла /etc/shadow.
2. Попытка просмотра каталога /root.
3. Чтение файла /etc/passwd.
4. Создание файла в каталоге /tmp.
5. Попытка просмотра файла /etc/sudoers.

Часть операций завершилась отказом в доступе, что было зафиксировано системой аудита.

### Хронология действий bob

| Действие | Результат | Источник |
|-----------|-----------|-----------|
| cat /etc/shadow | Отказ в доступе | ausearch -k access-denied |
| ls /root | Отказ в доступе | ausearch -k access-denied |
| cat /etc/passwd | Успешно | ausearch -k auth-files |
| Создание файла в /tmp | Успешно | ausearch |
| cat /etc/sudoers | Отказ в доступе | ausearch -k access-denied |

### Как auditd помог расследованию

Система auditd позволила определить:
- пользователя, выполнившего действия;
- время выполнения действий;
- объекты доступа;
- результат выполнения операций;
- факт неудачных попыток доступа.

На основании полученных данных удалось восстановить последовательность событий и определить источник подозрительной активности.

### Чем auditd лучше journalctl для задач аудита безопасности

journalctl ориентирован на просмотр системных журналов приложений и служб.

auditd работает на уровне ядра и фиксирует непосредственно системные вызовы.

Преимущества auditd:
- более высокая детализация событий;
- контроль доступа к файлам;
- контроль изменения конфигурации;
- возможность поиска по ключам правил;
- удобство расследования инцидентов безопасности.

## 6. Контрольные вопросы

### 1. Чем принципиально отличается auditd от journald? Почему нельзя обойтись только journald?

journald является системой журналирования Linux и собирает сообщения от служб, приложений и компонентов операционной системы.

auditd является специализированной системой аудита безопасности, работающей на уровне ядра. Он фиксирует системные вызовы, обращения к файлам и действия пользователей.

Использовать только journald недостаточно, поскольку многие события безопасности могут не попасть в обычные журналы. Auditd обеспечивает более детальный контроль действий пользователей.

---

### 2. Что такое auid и почему оно важнее uid при расследовании инцидентов с sudo?

AUID представляет собой идентификатор пользователя, который первоначально вошёл в систему.

UID показывает текущего пользователя процесса, а после использования sudo может стать равным root.

AUID сохраняет сведения об исходном пользователе и позволяет определить настоящего инициатора действий.

---

### 3. Что означает флаг -k в правиле auditd? Для чего он используется?

Флаг -k задаёт текстовый ключ для правила аудита.

Ключ используется для быстрого поиска событий через команду:

```bash
ausearch -k имя_ключа
```

Это значительно упрощает расследование инцидентов.

---

### 4. Чем -w отличается от -a always,exit в правилах auditd?

Параметр -w используется для наблюдения за конкретными файлами и каталогами.

Параметр -a always,exit применяется для контроля системных вызовов ядра.

-w используется для контроля объектов файловой системы, а -a always,exit — для контроля определённых действий пользователей.

---

### 5. Злоумышленник удалил файл /var/log/audit/audit.log. Как это помогает ему скрыть следы и как от этого защититься?

Удаление журнала позволяет скрыть информацию о действиях нарушителя.

Для защиты необходимо:
- ограничить доступ к журналам;
- использовать удалённое хранение логов;
- контролировать удаление журналов через auditd;
- выполнять резервное копирование журналов.

---

### 6. Что нужно сделать чтобы правила auditd сохранились после перезагрузки?

Необходимо создать файл правил в каталоге:

```bash
/etc/audit/rules.d/
```

После этого следует выполнить команду:

```bash
sudo augenrules --load
```

Правила будут автоматически загружаться при запуске системы.
